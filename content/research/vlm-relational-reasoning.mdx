## What the study asks

Vision-language models are increasingly evaluated on benchmark leaderboards run against large cloud-hosted checkpoints. This study asks a narrower, more practical question: how does relational and spatial reasoning performance hold up as you move the same class of model down a compute spectrum — from a cloud API, to a local workstation GPU, to an 8GB NVIDIA Jetson edge device? That question matters for anyone deciding whether a VLM-based reasoning task can actually run at the edge rather than only in a demo.

**Publication status:** Preprint in preparation — arXiv link coming soon.

## The engineering

Most of the work in this project was building an evaluation harness that could run unattended for days at a time, not the modeling itself.

- **Evaluation harness and monitoring** built specifically for unattended, multi-day data collection — the harness needed to detect and recover from failures without a person watching it.
- **2,000-item balanced evaluation set**, collected with a paired design so the same items are evaluated across every point on the compute spectrum.
- **Hypotheses and analysis plan frozen in version control before data collection began** — a pre-registration discipline applied to an engineering evaluation, not just the usual academic context.
- **Edge-deployment debugging over SSH on a headless device**, including:
  - Diagnosing kernel out-of-memory kills from system logs alone, with no display attached.
  - Isolating GPU memory failures to specific inputs rather than treating them as random crashes.
  - Relocating model storage after running into a full disk mid-run.
  - Building a clean resume path so an interrupted run could pick back up without re-collecting completed items.
- The harness **survived two unplanned power losses without losing collected data** — a direct result of the resume-on-interruption design above.

## Methodology, at a high level

The evaluation compares the same family of vision-language model across three deployment points on the compute spectrum — a cloud API, a local GPU workstation, and an 8GB Jetson edge device — on a shared, balanced 2,000-item relational and spatial reasoning set, using a paired collection design so every item is evaluated under the same conditions at each compute tier.

Results will be published with the preprint.
